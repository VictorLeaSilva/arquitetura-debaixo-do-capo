## Objetivo
Fazer o build do backend reprovar sozinho o código mal formatado, os bugs comuns, a cobertura abaixo do piso e as violações de arquitetura, e fazer o GitHub rodar esse build e um detector de segredos em todo PR, para que cada tarefa seguinte já nasça dentro dos gates (`04 §1`, G2 e G3). Também elimina o aviso do Mockito (Q-013).

**Testes de arquitetura (RNF-004), em `backend/src/test/java/io/github/victorleasilva/capo/architecture/`:**
- `ArchitectureRules`: classe utilitária `final`, com as regras como constantes `public static final ArchRule`:
  - `DOMAIN_IS_FRAMEWORK_FREE` (AC-RNF-004.1): nenhuma classe em `..inventory.domain..` ou `..ordering.domain..` depende de `org.springframework..`, `jakarta.persistence..` ou `org.hibernate..`;
  - `EXPERIMENT_ONLY_FROM_LAB_OR_EXPERIMENT` (AC-RNF-004.2): só classes de `..lab..` e de `..experiment..` dependem de classes de `..experiment..` (dependências dentro do mesmo pacote `experiment` são permitidas);
  - `MODULES_TALK_ONLY_THROUGH_API` (AC-RNF-004.3): para os módulos `catalog`, `inventory`, `ordering` e `lab` (o segmento logo abaixo do pacote base), uma classe de um módulo só depende de classe de **outro** módulo se esta estiver no pacote `api` desse outro módulo, ou no pacote `experiment` dele quando quem depende está em `..lab..` ou em `..experiment..`;
  - `NO_FLOATING_POINT_MONEY` (AC-RNF-004.4): nenhum campo cujo nome contenha `price`, `amount`, `total` ou `cost` (sem diferenciar maiúsculas) tem tipo `double`, `float`, `java.lang.Double` ou `java.lang.Float`.
  - Todas com `.allowEmptyShould(true)`: os módulos ainda não existem; sem isso, o ArchUnit reprova uma regra que não encontrou nenhuma classe.
- `ArchitectureTest` (`@Tag("RNF-004")`): aplica as 4 regras às classes de produção de `io.github.victorleasilva.capo` (importadas com `ImportOption.DoNotIncludeTests`).
- `ArchitectureRulesTest` (`@Tag("RNF-004")`): prova que **cada** regra pega uma violação. Para cada regra, importa as classes de `io.github.victorleasilva.archfixtures` (um pacote **fora** do pacote base, só em `src/test`, para nunca entrar na verificação de produção) e verifica que a regra **falha** sobre a violação proposital e **passa** sobre um exemplo correto. As classes de fixture ficam em:
  - `archfixtures.inventory.domain.SpringDependentEntity` (usa uma anotação do Spring) e `archfixtures.inventory.domain.PureEntity`;
  - `archfixtures.catalog.UsesOrderingExperiment` (usa `archfixtures.ordering.experiment.NaiveThing`) e `archfixtures.lab.UsesOrderingExperiment` (permitido);
  - `archfixtures.catalog.UsesOrderingInternal` (usa `archfixtures.ordering.internal.Hidden`) e `archfixtures.catalog.UsesOrderingApi` (usa `archfixtures.ordering.api.Facade`, permitido);
  - `archfixtures.catalog.DoublePrice` (campo `double unitPrice`) e `archfixtures.catalog.DecimalPrice` (campo `BigDecimal unitPrice`).
  - As regras recebem o pacote base como parâmetro (`ArchitectureRules` expõe métodos `forBase(String)` ou equivalentes), para valer tanto para `io.github.victorleasilva.capo` quanto para `io.github.victorleasilva.archfixtures`.

## Critérios de aceite
- **AC-RNF-004.1** Dada uma classe em `..inventory.domain..` que usa uma anotação do Spring, quando `DOMAIN_IS_FRAMEWORK_FREE` é avaliada, então a regra falha; sobre uma classe pura, passa; e sobre o código de produção atual, passa.
- **AC-RNF-004.2** Dada uma classe de `..catalog..` que usa uma classe de `..ordering.experiment..`, quando `EXPERIMENT_ONLY_FROM_LAB_OR_EXPERIMENT` é avaliada, então falha; vinda de `..lab..`, passa.
- **AC-RNF-004.3** Dada uma classe de `catalog` que usa `ordering.internal.Hidden`, quando `MODULES_TALK_ONLY_THROUGH_API` é avaliada, então falha; usando `ordering.api.Facade`, passa; e a classe de `lab` que usa `ordering.experiment` também passa.
- **AC-RNF-004.4** Dada uma classe com o campo `double unitPrice`, quando `NO_FLOATING_POINT_MONEY` é avaliada, então falha; com `BigDecimal unitPrice`, passa.
- **AC-T002.1** Dado um espaço a mais, proposital, no fim de uma linha de `CapoApplication.java`, quando `./mvnw -q verify` é executado, então o build falha citando o Spotless; depois de `./mvnw spotless:apply`, volta a passar.
- **AC-T002.2** Dado um método temporário em `CapoApplication` que compara strings com `==`, quando `./mvnw -q verify` é executado, então o build falha com o achado do SpotBugs `ES_COMPARING_STRINGS_WITH_EQ`; ao remover o método, volta a passar.
- **AC-T002.3** Dada uma classe temporária de produção com 10 linhas executáveis e nenhum teste, quando `./mvnw -q verify` é executado, então o `jacoco:check` falha citando o mínimo de `0.70`; ao remover a classe, volta a passar, e `backend/target/site/jacoco/index.html` existe.
- **AC-T002.4** Dado o build completo, quando `./mvnw -q verify` é executado no Git Bash e no Windows PowerShell 5.1, então termina com código `0`, e a saída não contém a frase `A Java agent has been loaded dynamically`.
- **AC-RNF-005.1** Dado o mesmo commit, quando `./mvnw -q verify` é executado 3 vezes seguidas, então as 3 execuções terminam com código `0` e com os mesmos totais de testes (executados, falhas, erros, ignorados).
- **AC-T002.5** Dado um PR desta tarefa no GitHub, quando o workflow `ci` roda, então os jobs `build`, `secrets` e `dependency-review` terminam verdes; todas as linhas `uses:` do arquivo apontam para um SHA de 40 caracteres seguido do comentário da tag; e o workflow tem `permissions: contents: read`.
- **AC-RNF-009.3** Dado o repositório, quando o job `secrets` roda no PR, então termina sem achados; e, rodando o gitleaks 8.30.1 localmente (imagem Docker oficial) sobre uma pasta temporária fora do repositório com uma chave AWS de exemplo, ele reporta o achado.
