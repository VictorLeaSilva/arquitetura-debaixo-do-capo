**`scripts/doc-lint.sh`** (POSIX: bash, awk, grep e sed; roda no Git Bash e no `ubuntu:24.04` com mawk e `LANG=C.UTF-8`; aceita CRLF):
1. Uso: `bash scripts/doc-lint.sh [arquivo ...]`. Sem argumentos, confere `site/docs/como-estudar/modelo-de-pagina.mdx` e todo `.md` e `.mdx` em `site/docs/experimentos/` (recursivo; a pasta pode não existir). Um arquivo passado que não existe → `ERRO arquivo não encontrado: <arquivo>` e exit 2.
2. **Seções (AC-010.2):** uma seção é uma linha `## <nome>` fora de bloco de código, comparada com o nome exato (espaços no fim ignorados). As 13 seções do AC-010.2 precisam aparecer uma vez cada, nesta ordem; outros títulos `##` podem aparecer entre elas. O conteúdo não é conferido ("Não se aplica" passa).
3. **Blocos de código (AC-010.3):** um bloco abre numa linha que começa (depois de espaços) com três ou mais crases e fecha na próxima linha com crases. A linguagem é a primeira palavra depois das crases. Sem linguagem → erro. Linguagem de terminal (`bash`, `sh`, `shell`, `console`, `powershell`, `pwsh`, `ps1`, `cmd`) → o bloco precisa estar dentro de um `<Tabs ... groupId="shell" ...>` (até o `</Tabs>` correspondente). Um grupo `shell` precisa ter um `<TabItem` com `value="bash"` e outro com `value="powershell"`. Grupos de abas aninhados não são aceitos.
4. Mensagens (uma por problema; todos os problemas aparecem antes de sair):
   | Situação | Mensagem |
   |---|---|
   | seção ausente | `ERRO <arquivo>: falta a seção "<nome>"` |
   | seção repetida | `ERRO <arquivo>:<linha>: seção repetida "<nome>"` |
   | seção fora de ordem | `ERRO <arquivo>:<linha>: seção fora de ordem "<nome>"` |
   | bloco sem linguagem | `ERRO <arquivo>:<linha>: bloco de código sem linguagem` |
   | terminal fora das abas | `ERRO <arquivo>:<linha>: bloco <linguagem> fora de um grupo de abas groupId="shell"` |
   | grupo sem uma das abas | `ERRO <arquivo>:<linha>: grupo de abas shell sem a aba <bash\|powershell>` (linha do `<Tabs`) |
5. Saída: com erros, exit 1; sem erros, `doc-lint: ok (<N> páginas)` e exit 0.

## Critérios de aceite
- **AC-010.1** Dado o site em `site/`, quando `npm run build` é executado, então termina com código 0; e um link interno quebrado (em Markdown ou por caminho), inserido de propósito, faz o build falhar.
- **AC-010.2** Dada cada página de estudo (a página-modelo e as de `site/docs/experimentos/`), quando `scripts/doc-lint.sh` roda, então ele confirma as 13 seções na ordem; uma página sem uma delas faz o script sair com código 1, citando o arquivo e a seção que falta.
- **AC-010.3** Dado um bloco de código numa página de estudo, quando o verificador roda, então um bloco de terminal fora de um grupo `groupId="shell"` com as abas `bash` e `powershell`, ou um bloco sem linguagem, faz o script sair com código 1, citando o arquivo e a linha.
- **AC-010.5** Dado que a pessoa escolheu a aba PowerShell na página-modelo, quando abre a página "Comece aqui", então a aba PowerShell já vem selecionada.
- **AC-RNF-006.1** Os casos de AC-010.2 e AC-010.3 têm testes de script, com uma página válida e uma página para cada tipo de falha, e rodam no CI.
- **AC-T006.1** Dados os arquivos reais, quando `bash scripts/doc-lint.sh` roda no Git Bash e no `ubuntu:24.04` com `LANG=C.UTF-8`, então sai com `doc-lint: ok (1 páginas)` e código 0.
- **AC-T006.2** Dado o site, quando `npm run verify` roda em `site/` (Node 26), então tipos, lint, formatação e build terminam com código 0.
- **AC-T006.3** Dado um `package.json` com uma dependência fora de `allowed_new_dependencies`, quando o gate roda, então o item 3 reprova citando `nome@versão`.
